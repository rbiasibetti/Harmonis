Implantação (para TI)

Resumo técnico para quem instala, configura e mantém o Harmonis. O passo a passo completo, com comandos, está no README.md do repositório.

Banco de dados e migrations

  • Não há ferramenta de migração automática: os scripts em migrations/ são aplicados manualmente, em ordem (o utilitário tools/MigrationRunner.java ajuda).
  • Todas as tabelas do Harmonis usam o prefixo hm_, convivendo com tabelas de outros sistemas no mesmo banco.
  • Catálogo: migrations/catalog/*.sql. Cada empresa: migrations/tenant/*.sql (identidade, formulários, workflow, documentos, portal, anexos, integrações, sessões/refresh tokens, idiomas, assinaturas, modelos de dados).
  • Ao atualizar a aplicação, aplique os novos scripts em cada banco de empresa antes de subir a nova versão.

Provisionar uma nova empresa

  1. Crie o banco da empresa (ex.: harmonis_acme) no SQL Server.
  2. Registre-a no catálogo (tabela hm_tenants: nome, slug, nome do banco).
  3. Aplique, em ordem, todos os scripts de migrations/tenant/ no banco da empresa.
  4. Semeie papéis, permissões e o proprietário iniciando o backend com --harmonis.seed.tenant=<slug>. Use --harmonis.seed.owner-name, --harmonis.seed.owner-email e --harmonis.seed.owner-password para definir o proprietário.
Senha do proprietário

Se você não informar --harmonis.seed.owner-password, a senha inicial do proprietário é password (somente para demonstração). Como a interface ainda não permite trocar a própria senha, defina uma senha forte já no provisionamento.

Reexecutar o seed

O seed é idempotente: pode ser repetido para incluir novas permissões nos papéis de sistema após uma atualização (por exemplo, as de Integrações). Usuários precisam entrar de novo para receber as novas permissões.

Em produção

  • HTTPS sempre; sirva o frontend (arquivos estáticos gerados) e encaminhe /api ao backend.
  • Ative HARMONIS_COOKIE_SECURE=true (HTTPS). Os tokens de sessão ficam em cookies HttpOnly com proteção CSRF e refresh token rotativo (reuso revoga a sessão).
  • Troque HARMONIS_JWT_SECRET e HARMONIS_SECRET_KEY; use usuário de banco com o mínimo de privilégios; restrinja HARMONIS_CORS ao seu domínio.
  • Backups: bancos (catálogo + um por empresa) e a pasta de arquivos (HARMONIS_DOCS_DIR) — os dois precisam ser restaurados juntos.
  • Logs de integração não são expurgados automaticamente: planeje uma rotina de retenção para a tabela hm_integration_log.
  • Fila de webhooks em memória: um reinício do backend com retentativas pendentes as descarta (o último estado fica nos logs e o reenvio manual está disponível).
  • Webhooks para rede interna: habilite HARMONIS_WEBHOOK_ALLOW_PRIVATE apenas se necessário e entenda o impacto (o backend passa a poder alcançar a rede interna).
  • Monitore o espaço em disco da pasta de arquivos (limite de 10 MB por arquivo).

Limitações conhecidas desta versão

  • Sem tela para troca/recuperação de senha.
  • Formulários com processos de aprovação podem ser recusados na exclusão.
  • Portal sem suporte a tabelas Markdown nem upload de imagens.
  • Provisionamento de empresa é manual (não há cadastro automático).
